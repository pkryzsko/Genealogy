# Geni OAuth review and owner handoff

Reviewed 2026-11-03. **No authenticated Geni request has succeeded in this
environment.** Tests below are offline; mocked responses are not evidence of access.

## Diagnosis of the implementation on main

| Requirement | Existing behavior |
| --- | --- |
| Official endpoints | Token endpoint correct; no browser authorization URL builder. |
| Required redirect | Code exchange omits redirect_uri when GENI_REDIRECT_URI is unset. This violates the documented requirement. |
| Identical redirect | No stored authorization request against which to compare the exchange redirect. |
| OAuth state | No state generation, persistence, expiry, or validation. |
| Refresh | Both refresh paths omit redirect_uri. |
| Read-only / GEDCOM | API client uses GET with Bearer headers; GEDCOM is independent of OAuth. |
| Confidential output | whoami/path/run print personal data; API and token errors can include server-provided content. |

The original browser authorization URL is unavailable and is not generated by
main's importer. Changing only the exchange redirect cannot repair that URL.
Application 2290's registered Site Domain and Callback URL remain unverified.

The support account supplied by the owner (ticket #203513, Mike, October 19,
2026) identifies localhost rejection as a plausible original cause. It has not
been independently reproduced. No firewall evasion or automated login was attempted.

Checked Geni's official [server-side documentation](https://www.geni.com/platform/developer/help/oauth_server_side?version=1)
and [OAuth introduction](https://www.geni.com/platform/developer/help/oauth_intro).
The redirect must belong to the configured Site Domain and match across the
authorization and exchange steps. Refresh also requires the original redirect.
State is returned to the callback for validation. Read scope must be explicit;
omitting scope defaults to full access.

## Correction in this draft

- Add auth-url using the official authorization endpoint, response_type=code,
  scope=read_profile, and a cryptographically random state.
- Require an absolute HTTP(S) GENI_REDIRECT_URI; reject localhost callbacks.
  For this small manual flow, callbacks with a query or fragment are unsupported.
  Site Domain compatibility must still be verified in Geni settings by the owner.
- Save state, client id, and the exact unmodified redirect outside the repository,
  in ~/.geni/oauth-state.json. Reject absent, wrong, expired (10 minutes), or used
  state, and changed redirect/client configuration before any token request.
  Starting auth-url again replaces the previous pending authorization.
- Have auth prompt privately for the code and **state returned in the callback**.
  Consume state before exchange; a failed exchange requires starting over.
  Existing --code / GENI_AUTH_CODE inputs remain, but valid returned state is now
  mandatory (--state / GENI_AUTH_STATE also supported). Bare external code exchange
  intentionally fails closed.
- Send the exact saved redirect and explicit authorization_code grant in the token
  POST. Include the original redirect in refresh requests and remember it with
  newly stored tokens. Legacy token files lack this metadata: the owner must set
  their original redirect before refreshing them.
- Write token and pending-state files atomically with mode 0600 from creation.
  Suppress server error bodies/descriptions and transport details.
- Add check: GET /api/profile?fields=id, Bearer header, success only when an id
  is present. Output confirms receipt without printing the id or other profile data.
  Existing read-only commands and GEDCOM behavior are preserved.

No app registration or environment settings were changed. No Geni profiles or
relationships were changed.

## Precise owner action

1. In Geni developer settings for application 2290, inspect Site Domain and Callback
   URL. Select an owner-controlled hostname and callback path consistent with those
   settings; update the settings if needed. Configure GENI_REDIRECT_URI to that
   exact URL, including scheme, port, path, and trailing slash.
2. Arrange a trusted callback destination that does not log query strings or load
   third-party assets. This CLI has no web listener: it uses manual code/state
   transfer. If using the local hosts-file approach suggested by support, configure
   that hostname on the machine running your browser and run the callback receiver
   there. It is not sufficient to edit a remote Codex machine's hosts file.
   Do not substitute IPs or alternate routing to evade a Geni restriction.
3. Securely configure GENI_APP_SECRET (and GENI_APP_ID if different from 2290) on
   that same trusted machine. Do not put credentials in shell command arguments,
   chat, commits, or shared logs. Keep all OAuth steps in the same local account.
4. Run python3 tools/geni_import.py auth-url in a private terminal. Open that URL
   in your own browser, log in manually, and verify the consent screen grants
   read-only access. **This is the required human authorization step.**
5. Within ten minutes, run python3 tools/geni_import.py auth. At its hidden prompts,
   enter the URL-decoded code and state from the returned callback query, not
   the original authorization URL. Do not paste the full callback into chat.
   Keep GENI_REDIRECT_URI unchanged. Prompts fail closed if input cannot be hidden.
6. Run python3 tools/geni_import.py check. A success message from this real request
   is the acceptance criterion. Record only success/failure and HTTP status on
   error. Do not use whoami, path, or run for a privacy-safe access check: their
   normal output includes personal data.

If Geni blocks the browser request, stop and privately provide its blocked-page
IP and Incident ID to support under ticket #203513. Neither was available here.
Do not bypass the firewall or automate CAPTCHA/login.

For a later check in Codex, its supported environment network configuration must
allow www.geni.com and credentials must be supplied securely. The current enforced
policy excludes Geni; there are no bound secrets, all importer GENI variables
are unset, and ~/.geni/token.json is absent. These independently block live
verification. Existing access-token use does not require the new OAuth settings.
